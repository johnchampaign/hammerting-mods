# Hammerting mods

Each folder here is one mod: a `mod.py` that patches the game's own files. The builder
applies the mods you pick and writes them into a single archive that the game loads on
top of `game.wkz`. Nothing in the game install is changed except `danger_zone/` and, for mods marked
"DLL patch", `game.x86_64.dll` (and `entity.x86_64.dll`). Each original DLL is kept as
`<name>.hmod-orig`; installing without DLL-patch mods, `python3 tools/hmod.py uninstall`, or Steam's "Verify
integrity of game files" puts it back. Close the game before installing.

## Install

```bash
python3 tools/hmod.py list
python3 tools/hmod.py install recommended
```

`recommended` stands for the mods listed in `mods/recommended.txt`; edit that file, or name mods
on the command line instead, to choose your own set. Installing replaces the previous install.

Then in Steam, open Hammerting → Properties → General → Launch Options and set:

```
%command% --game-extra-archives danger_zone/hammerting_mods.wkz
```

To turn autosaves off entirely (manual saves still work), add `--gamestate-autosave false`
to the launch options; this needs no mod.

To play unmodded, clear the launch options. The archive can stay where it is.

## Writing a mod

`mods/<name>/mod.py` needs `DESCRIPTION` and `apply(ctx)`:

- `ctx.read(name)` / `ctx.write(name, data)` read and write archive files. Reads see
  earlier mods' changes.
- `ctx.loc('cave')` returns `localization/cave.loc` as an editable `LocTable` (see
  `tools/loc.py`). `.key('KEY_NAME').text` is a string's text.
- `ctx.replace_cstr(file, old, new)` rewrites a string held in a fixed zero-padded
  buffer, such as the eval chains in `database/**/*.bin` records.
- `tools/evalchain.py` builds compiled expression blobs for `.loc` entries: `compile_chain(source)` compiles new ones,
  and `retarget` renames properties in an existing one.
- `ctx.patch_dll(va, old, new, note, dll='game')` replaces bytes in `game.x86_64.dll` (or
  `dll='entity'` for `entity.x86_64.dll`; see `dllpatch.DLLS`) at a virtual address. `old`
  must match the original 1.2.39 bytes, so a wrong address fails at build.
- Code caves go in the `.hmod` section that `tools/dllpatch.py` appends (`dllpatch.CAVE_VA`,
  4 KB, zero-filled, so `old` is zeros). `whole_batch_inputs` has the first 0x100 bytes reserved
  (the ranges in use are listed in `CLAUDE.md`);
  give each new cave its own range. `tools/cave.py` assembles a cave source with llvm-mc and keeps the
  result in `tools/cave_cache/`, so players without llvm-mc can still install; rebuild with llvm-mc after
  changing a cave or its settings.
